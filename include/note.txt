std::vector<Client> clients --> je creer un conteneur , les objets contenu dedans seront des objets de type Client et clients est le nom de la variable.
C'est un tableau dynamique. A chaque fois qu'un objet Client est creer il sera stocké dans ce tableau .

Quand on creer un socket , cela retourne un fd et ce fd sera l identifiant du socket.
On surveille le fd avec poll();
std::vector<pollfd> fds --> Un tableau ou on stocke tous les fd des sockets presents dans le programme.
Quand un client se connecte on ajoute un nouveau pollfd dans ce vecteur et quand il se deconncte on supprime du tableau son pollfd
Ce vector fds sera envoye a poll() qui va surveiller s'il y a eu des evenements dans des sockets. 
C'est un tableau de structure  qu'on envoie a poll() et non seulement le int fd. Cette structure contient tous les infos necessaires que poll() a besoin.
struct pollfd {
    int   fd;        // Le file descriptor que tu veux surveiller
    short events;    // Ce que tu veux écouter (ex : POLLIN pour lecture) , evenmt a surveiller
    short revents;   // Ce qui s’est vraiment passé (rempli par poll()) , evenemnt detecter
};







🧭 En pratique, que surveiller pour ton serveur ?

Tu vas typiquement surveiller ces deux événements pour chaque socket :

POLLIN → pour savoir si tu dois lire quelque chose

POLLHUP → pour savoir si un client s’est déconnecté

Et tu vérifieras aussi :

Si recv() retourne 0 → déconnexion propre

Si revents contient POLLERR → erreur grave → tu fermes aussi
