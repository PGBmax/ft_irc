Si revents contient POLLERR → erreur grave → tu fermes aussi

Quand on crée un socket, on doit dire quel genre de communication on veut mettre en place. Ça se définit avec trois choix :
*Le DOMAINE d'ADRESSAGE(famille d’adresses) → sur quel réseau on veut travailler
    IPv4 : les adresses classiques 192.168.x.x  --> AF_INET
    IPv6 : les adresses plus longues 2001:0db8:...
👉 En gros : est-ce qu on veut un serveur qui parle IPv4, IPv6, ou autre (Unix local, etc.).

*Le TYPE → comment on veut que les données circulent
    Stream (TCP) : communication fiable, ordonnée, sans pertes. Comme un appel téléphonique.
👉 Pour un serveur IRC, c’est forcément stream (TCP). --> SOCK_STREAM

*Le PROTOCOLE → le protocole utilisé avec ce type
    La plupart du temps, quand on dit "Stream" on veut dire TCP.
    Du coup on met presque toujours 0 pour laisser le système choisir automatiquement le bon protocole. --> 0

createSocket():
- 1: creer un socket : this->_serverSocketFd = socket(AF_INET, SOCK_STREAM, 0);
-->crée un socket serveur TCP en IPv4.

- 2 : on configure le serveur avec setsockopt()
SO_REUSEADDR → l’option en question.
Ça permet de : si on arrête le serveur puis on le relances tout de suite sur le même port, 
sans cette option on pourrait avoir l’erreur Address already in use et Avec SO_REUSEADDR, on évite cela.

- 3 : on rend le serveur non bloquant avec fcntl()
--> Sans O_NONBLOCK → le serveur reste figé dès qu’il attend un client ou des données.
--> Avec O_NONBLOCK → le serveur ne bloque pas, il peut vérifier régulièrement s’il y a des clients ou des messages
et faire d’autres tâches en même temps.
En mode O_NONBLOCK,le serveur peut continuer à tourner et faire autre chose même s’il n’y a aucune connexion ou message entrant.

- 4 : on associe le socket a une adress IP et un port avec bind()
--> C’est ce qui fait que le serveur écoute sur une adresse précise et que les clients savent où se connecter.

- 5 : on passe le socket en mode ECOUTE avec listen();
 "Ok, mon socket est maintenant un serveur. Il peut écouter les clients qui veulent se connecter. 
 Les clients qui arrivent sont mis dans une file d’attente si je ne peux pas les accepter tout de suite."

struct sockaddr_in contient uniquement :
IP du client (sin_addr)
Port du client (sin_port)
Famille d’adresse (sin_family, toujours AF_INET pour IPv4)

len = taille de la structure d’adresse client → nécessaire pour que accept() fonctionne correctement.
O_NONBLOCK → flag qui rend le fd non-bloquant.
En d’autres termes : on rend le socket du client non bloquant, ce qui permet au serveur de lire 
ou écrire dessus sans jamais se bloquer si aucune donnée n’est disponible.

POLLIN est un flag qu’on met dans events pour dire :
« Je veux être prévenu quand il y a des données à lire sur ce fd. »
Quand le client envoie des données, le socket devient lisible.
poll() va alors remplir revents pour ce fd, indiquant que POLLIN est déclenché.
Le serveur peut alors lire le fd correspondant sans bloquer.
POLLIN = le serveur surveille si le client a écrit quelque chose et reçoit l’info via revents.

    recv() : Client écrit → les octets vont dans le tampon de la socket côté kernel.
            Serveur appelle recv → kernel copie les octets dans le buff serveur.

    si 0 → client a fermé la connexion proprement
